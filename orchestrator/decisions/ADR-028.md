# ADR-028 — Selective adversarial callback (controlled, caller-driven)

**Status:** Accepted · **Date:** 2026-06-02 · **Supersedes:** none
**Replaces:** previous mention of M11.1 in roadmap

## Context

The 4-LLM ensemble in `gate_decider` (Claude + GPT + Gemini + Grok) reliably
catches obvious bad PASS / KILL calls when ≥3 agree (M9.0). But in the
borderline band — `final_confidence ∈ [0.6, 0.8]` — a 3-of-4 majority can
mask a subtle issue that no individual lens spotted because all four lenses
were asked the same question.

The original architectural rule (`orchestrator/CLAUDE.md`) explicitly forbids
a Governor anti-pattern: *"No crear un Governor/orquestador que decida
dinámicamente qué agente llamar."* That rule prevents runaway tool-use
loops but it also prevents the legitimate need to ask "could we be wrong
in a way none of us thought about?"

We need a way for `gate_decider` to invoke a **specific** adversarial check
in a **specific** confidence band, without opening the door to free
conversation between agents.

## Decision

Add a **hard-coded, single-direction, opt-in** callback from `gate_decider`
to `MultiAgentConsensus`:

```
if 0.6 <= gate_result.final_confidence <= 0.8:
    adversarial = MultiAgentConsensus.run(
        prompt=ADVERSARIAL_TEMPLATE.format(
            verdict=gate_result.final_verdict,
            rationale=gate_result.summary,
        ),
        target_role="skeptic",  # explicit lens, hard-coded
    )
    if adversarial.serious_objections_count >= 2:
        gate_result.final_verdict = "iterate"  # degrade
        gate_result.degraded_by = "adversarial_callback"
```

### Why this is NOT a Governor

- The callback is **hard-coded** in `gate_decider`. No LLM decides who to
  call.
- The callback is **one-shot**: `gate_decider` → `consensus`, period.
  Consensus cannot call back.
- The callback is **bounded by a confidence band**: 100% certain calls
  (>0.8) and clear kills (<0.6) skip it entirely. So in the worst case the
  extra cost is **+1 LLM call on ~30% of runs**.
- The callback has a **specific role**: "find 3 reasons this verdict is
  wrong." Not free conversation, not "what do you think?".

## Consequences

### Positive
- Catches subtle wrong-PASS calls that all 4 LLMs miss because they share
  RLHF priors (the same reason we added Grok in M9.0, applied recursively
  one level deeper).
- Cost-bounded: ~30% of runs × $0.04 (consensus cost) = ~$1.20 per 100 runs.
- Fully testable: golden cases pin the band edges (0.59 → no callback,
  0.61 → callback fires).
- Discoverable in logs: every degraded verdict logs `degraded_by`.

### Negative
- Slight latency hit on borderline runs (+5s for consensus).
- Adds a coupling between two agents — `MultiAgentConsensus` is no longer
  pure on-demand; `gate_decider` depends on it for M11.1+.

### Mitigations
- If consensus is unavailable (missing keys, API down), the callback fails
  open: `gate_decider` returns its original verdict and logs the failure.
- The band [0.6, 0.8] is tunable via env (`M111_ADV_BAND_LOW`,
  `M111_ADV_BAND_HIGH`) so we can widen/narrow it based on observed
  false-PASS rate.

## When to revisit

Three concrete signals would force us to revisit this ADR:

1. **False-PASS rate > 15%** after 30 runs with the callback active.
   → Widen the band to [0.5, 0.9] or add a second adversarial check (Grok
   alone) BEFORE consensus.
2. **Callback firing on >50% of runs**.
   → Either calibrate `gate_decider`'s confidence scoring (most likely
   issue is over-confident agreement in the 0.6-0.8 band) or narrow the
   band.
3. **Cost crosses $50/month from callbacks alone**.
   → Replace `MultiAgentConsensus` with a cheaper single-Grok adversarial
   prompt (Grok is the best contrarian voter empirically — M9.0 commit
   `e6f7761` rationale).

## What this is NOT

- ❌ NOT a Governor that decides which agent to call dynamically.
- ❌ NOT free conversation — every callback is hard-coded.
- ❌ NOT recursive — consensus cannot trigger another callback.
- ❌ NOT applied outside `gate_decider` — workflow body stays linear.
